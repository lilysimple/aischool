# Обложка и публикация

Обложка не генерируется нейросетью. Берётся фотография автора, поверх
кладётся свёрстанная плашка из `templates/cover.html`, и со страницы
снимается скриншот. Поэтому результат предсказуем, а поправить отступ —
это одна строка CSS, а не двадцать попыток с промптом.

## Шаг 1. Подбери 2–3 фото

Посмотри, что есть в `input/photos/`. Если рядом лежит `index.json`
с описаниями — читай его, это быстрее. Если файла нет, открой фотографии
через Read, посмотри на них и составь `index.json` один раз:

```json
[{"file": "IMG_1.jpg", "what": "рабочий стол, ноутбук, блокнот", "mood": "спокойное, дневной свет"}]
```

Дальше выбирай кандидатов по смыслу поста, а не по порядку в папке.
Что учитывать:

- фото не должно спорить с темой: к посту про выгорание не идёт
  фотография с застолья;
- нужно место под плашку внизу кадра — сюжет, забитый деталями
  по нижнему краю, читается плохо;
- проверь по `state/ideas-history.jsonl`, не использовалось ли фото
  в последних пяти постах.

## Шаг 2. Спроси автора

```
python3 scripts/tg_ask_photo.py input/photos/a.jpg input/photos/b.jpg --question "Какое фото ставим?"
```

Скрипт пришлёт кандидатов пронумерованными, дождётся ответа с номером
и напечатает путь к выбранному файлу. Выбирает человек — не решай за него,
даже если один вариант кажется очевидным.

## Шаг 3. Собери обложку

```
python3 scripts/render_cover.py <выбранное фото> \
  --title "<title из meta.json>" \
  --kicker "<kicker из meta.json>" \
  --handle "<BRAND_HANDLE из .env>" \
  --out output/<дата>/cover.png
```

Открой получившийся PNG через Read и посмотри на него сам, до автора.
Ищи:

- заголовок, вылезший за плашку или обрезанный;
- нечитаемый текст из-за светлого фото — лечится увеличением
  `--photo-dim` в `templates/cover.html`;
- важную деталь снимка, закрытую плашкой;
- пустую плашку — значит, в `meta.json` пустой `title`.

Заголовок длиннее 90 знаков скрипт не пропустит и скажет об этом.
Если текст в лимите, но всё равно вылезает, проблема в CSS: чини
`templates/cover.html`, а не подгоняй заголовок под баг.

## Шаг 4. Покажи автору и опубликуй

Отправь обложку и финальный текст через `scripts/tg_ask.py`
и дождись «ок». Это последняя точка контроля перед публичным каналом —
не пропускай её.

После «ок»:

```
python3 scripts/publish_telegram.py output/<дата>
```

Скрипт сам проверит длину текста и разметку, опубликует пост
и вернёт ссылку. Перешли её автору.

## Шаг 5. Запиши в память

Допиши в `state/ideas-history.jsonl` одну строку:

```json
{"date": "ГГГГ-ММ-ДД", "title": "заголовок", "topic": "суть темы в 5 словах", "photo": "IMG_1.jpg", "url": "ссылка на пост"}
```

Пропускать нельзя. Без записи скилл `idea-finder` завтра предложит ту же
тему, а ты сам поставишь то же фото, и канал начнёт ходить по кругу.

## Если Telegram отказал

- `Bad Request: chat not found` — неверный `TELEGRAM_CHANNEL_ID`
  или бот не админ канала.
- `caption is too long` — текст длиннее 1024 знаков. Вернись
  к `post-writer` и сократи, а не режь по живому здесь.
- `can't parse entities` — в тексте тег, которого Telegram не понимает.
  Разрешены только b, i, u, s, a, code, pre, blockquote и tg-spoiler.
- `Conflict: terminated by other getUpdates request` — запущена вторая
  копия скрипта, закрой лишние окна терминала.

## Что считается сделанным

- фото выбрал автор, а не ты;
- на обложке нет обрезанного или нечитаемого текста;
- автор дал «ок» именно на обложку, а не только на текст;
- пост опубликован и ссылка отправлена автору;
- в `state/ideas-history.jsonl` появилась новая строка.
