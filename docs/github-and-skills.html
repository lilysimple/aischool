Что получится в конце

У вас будет аккаунт на GitHub, свой репозиторий с домашней работой и работающий скилл, который вы написали сами под свою задачу.

Главное — не аккаунт и не репозиторий. Главное вот что: вы перестанете каждый раз объяснять модели одно и то же. Промпт, который вы держите в заметках и копируете в чат по десять раз в неделю, станет файлом, который запускается фразой «сделай мне сводку по продажам» — и работает одинаково хорошо и сегодня, и через месяц.

Терминал не понадобится

Всё делается в браузере, мышкой. Если вы уже дружите с командной строкой — в конце каждого шага есть блок с командами, но это необязательный путь.

Зачем вам GitHub, если вы не программист

GitHub — это не только для кода. Это место, где текстовые файлы лежат с историей изменений: видно, что поменялось, когда и кем, и можно вернуться к любой прошлой версии.

Для вас в этом курсе у него три роли:

Забрать ОТКУДА БЕРЁМ

Проект агента лежит в репозитории курса. Скачали одной кнопкой — и у вас на компьютере вся структура папок, ничего не потеряно.

github.com/lilysimple/aischool

Ваши скиллы и настройки бренда — это текстовые файлы. На GitHub они не пропадут вместе с ноутбуком и будут доступны с любого устройства.

Создать свой репозиторий

5 минут · браузер
Что нужно на входе
  • аккаунт из шага 1
Что получится на выходе
  • пустой репозиторий ai-school-homework

Форк из шага 2 — это копия чужого проекта. Домашнюю работу удобнее сдавать в отдельном репозитории, где лежит только ваше.

Нажмите + в правом верхнем углу любой страницы GitHub → New repository. Заполните так:

ПолеЧто ставим
Repository name ai-school-homework — латиницей, без пробелов. Пробелы GitHub всё равно заменит на дефисы, лучше сразу писать правильно.
Description Одна строка: «Домашние работы курса AI School». Необязательно, но через месяц вы себе спасибо скажете.
Public / Private См. блок ниже — это единственное решение, которое здесь надо принять осознанно.
Add a README file Поставьте галочку. Без неё репозиторий создастся пустым, и GitHub покажет страницу с командами вместо файлов.

Нажмите Create repository.

Public или Private — что выбрать

Public видят все, включая будущих работодателей. Для учебных материалов это плюс: получается портфолио. Ссылку можно показывать.

Private видите только вы и те, кого вы пригласите. Выбирайте его, если в домашней работе будут внутренние данные компании, реальные тексты клиентов или что-то, что вы не готовы показать миру.

Поменять видимость можно в любой момент: Settings → General → в самом низу Danger Zone → Change visibility. Если сомневаетесь — начните с Private, открыть всегда проще, чем отозвать.

Запишите ссылку

Адрес вида github.com/ваш-логин/ai-school-homework — это и есть то, что вы сдадите в конце. Скопируйте его из адресной строки и сохраните.

Загрузить файлы мышкой

10 минут · браузер
Что нужно на входе
  • репозиторий из шага 3
  • любой файл для пробы — подойдёт текстовый
Что получится на выходе
  • файл лежит в репозитории
  • вы умеете обновлять его и видеть историю правок

Это навык, ради которого затевался весь первый блок. Потренируйтесь на черновом файле, прежде чем выкладывать работу.

Загрузка

На главной странице репозитория найдите кнопку Add file над списком файлов и выберите Upload files. Дальше перетащите файлы в окно браузера или нажмите choose your files.

Внизу страницы поле Commit message — это подпись к изменению. Оставлять её пустой можно, GitHub подставит своё, но привычка писать осмысленно окупается: через месяц вы будете листать историю и понимать, что происходило.

Так не надо
update, изменения, 1, asdf — не отвечает на вопрос «что изменилось».
Так работает
Добавила скилл для еженедельного отчёта, Поправила description, скилл не срабатывал.

Оставьте выбранным вариант Commit directly to the main branch и нажмите Commit changes. Файл появится в списке.

Про папки

Отдельной кнопки «создать папку» на GitHub нет — и это сбивает с толку. Папка появляется вместе с файлом: при загрузке перетащите папку целиком, либо в поле имени файла напишите путь через косую черту, например skills/weekly-report/SKILL.md. Гит создаст обе папки сам.

Из этого следует и обратное: пустую папку положить в репозиторий нельзя.

Как обновить файл, который уже лежит

Откройте файл в репозитории и нажмите на карандаш в правом верхнем углу. Правьте прямо в браузере, внизу снова Commit changes.

Каждое сохранение — отдельная точка в истории. Посмотреть все версии файла можно кнопкой History над его содержимым: слева даты и подписи, справа подсветка того, что именно изменилось — зелёным добавленное, красным удалённое. Это и есть то, ради чего стоит терпеть незнакомый интерфейс.

Два ограничения, о которые спотыкаются

Через браузер можно загрузить не больше 100 файлов за раз, и каждый не тяжелее 25 МБ. Папка с фотографиями для агента легко упирается в оба — её выкладывать и не нужно.

Если в файле окажется похожий на токен текст, GitHub заблокирует загрузку и покажет предупреждение. Это защита, а не ошибка: уберите секрет из файла и попробуйте снова.

Часть 2. Промпт становится скиллом

Дальше — то, ради чего задание придумано. Первая часть была про то, где хранить файлы. Эта — про то, что в них писать.

Скилл — это текстовый файл с инструкцией, который Claude Code подхватывает сам, когда вы формулируете задачу похожими словами. Никакого кода. Разница между промптом и скиллом не в сложности, а в том, что промпт живёт в вашей голове и в буфере обмена, а скилл — в файле, и работает одинаково у вас, у коллеги и через полгода.

Промпт РАЗОВЫЙ

Вы держите его в заметках, копируете в чат, каждый раз дописываете детали руками. Результат зависит от того, что вы не забыли добавить сегодня.

заметки · буфер обмена
Скилл ПОСТОЯННЫЙ

Лежит файлом, запускается обычной фразой, помнит все детали, включая те, что вы вспомнили на третий раз. Правится как обычный текст.

.claude/skills/имя/SKILL.md

Найти свой повторяющийся промпт

10 минут · честность с собой
Что нужно на входе
  • история ваших переписок с моделью
  • задача, которую вы делаете регулярно
Что получится на выходе
  • один выбранный промпт, записанный целиком

Откройте историю чатов и найдите то, что просите чаще всего. Не самое сложное — самое частое.

Признак хорошего кандидата: вы уже ловили себя на мысли «я это на прошлой неделе объяснял». Второй признак: результат вас устраивает не всегда, и вы дописываете уточнения в переписке.

Плохой кандидат
«Объясни, как работает нейросеть» — разовое любопытство. Ответ нужен один раз, повторять нечего.
Хороший кандидат
«Сделай сводку по недельным продажам из этой выгрузки» — делаете каждый понедельник, формат один и тот же, детали каждый раз объясняете заново.

Ещё примеры того, что хорошо ложится в скилл:

  • разобрать письмо клиента и предложить три варианта ответа;
  • переписать текст в тон вашей компании;
  • проверить документ по чек-листу, который у вас в голове;
  • собрать повестку встречи из переписки;
  • перевести описание задачи на язык, понятный подрядчику.

Выпишите выбранный промпт целиком, со всеми уточнениями, которые обычно дописываете в переписке. Это черновик — с ним будем работать дальше.

Не знаете, что выбрать — спросите модель

Откройте чат, где вы работаете чаще всего, и попросите: «Посмотри нашу переписку за последний месяц и назови три задачи, которые я прошу чаще всего». Список бывает неожиданным.

Разобрать устройство скилла

10 минут · чтение
Что нужно на входе
  • распакованный проект из шага 2
Что получится на выходе
  • понимание, из чего состоит SKILL.md

Откройте любой готовый скилл из проекта — например .claude/skills/post-writer/SKILL.md. Открывается он в обычном текстовом редакторе, это просто текст.

Файл устроен из двух частей:

---
name: post-writer
description: Пишет текст поста для Telegram-канала...
---

# Текст поста

Ты — автор канала, а не копирайтер вообще...

Сверху между двумя строчками из трёх дефисов — шапка. В ней два поля: name должно совпадать с именем папки, а description решает, когда скилл запускается.

Всё, что ниже, — тело: сама инструкция, которую модель прочитает, когда скилл сработает. Здесь вы пишете что и как делать.

Главное недоразумение новичков

description — это не краткий пересказ для человека. Это то, по чему Claude Code решает, запускать скилл или нет. Модель видит список описаний всех скиллов, сравнивает с вашей фразой и выбирает.

Отсюда правило: в описании должны быть слова, которыми вы реально формулируете задачу. Не те, которыми красиво называется процесс.

Где живёт скилл

Скиллы лежат в папке .claude/skills/. Одна папка — один скилл, внутри файл SKILL.md. Имя папки и есть имя скилла:

.claude/
  skills/
    weekly-report/
      SKILL.md
    client-reply/
      SKILL.md

Положите папку внутрь рабочего проекта — и скилл будет доступен в нём. Положите в домашнюю папку (~/.claude/skills/) — будет доступен везде. Для вашего первого скилла берите второй вариант, если задача не привязана к конкретному проекту.

Написать description

10 минут · текстовый редактор
Что нужно на входе
  • промпт из шага 5
Что получится на выходе
  • папка со скиллом и заполненной шапкой

Создайте папку и файл. Имя папки — латиницей, через дефис, по сути задачи: weekly-report, client-reply, doc-check.

Теперь самое важное поле во всём файле. Хорошее описание состоит из трёх частей: что делает, с чем работает и какими словами это просят.

Так не надо
description: Помогает с отчётами

Не сработает или сработает невпопад: под «помогает с отчётами» подходит половина возможных просьб.
Так работает
description: Собирает еженедельную сводку по продажам из выгрузки CSV: считает выручку по менеджерам, сравнивает с прошлой неделей и отмечает отклонения больше 15%. Триггеры - "сводка за неделю", "отчёт по продажам", "посчитай выручку", "сравни с прошлой неделей".

Приём, который экономит время: выпишите пять-шесть фраз, которыми вы на самом деле формулируете эту задачу, включая небрежные, и вставьте их в описание после слова «Триггеры». Именно небрежные формулировки и встречаются в жизни чаще всего.

Проверка описания на прочность

Прочитайте своё описание и спросите: подойдёт ли оно к трём другим задачам, которые я тоже делаю? Если да — оно слишком общее, скилл будет запускаться не вовремя. Добавьте конкретики: с какими файлами работает, что именно считает, что отдаёт на выходе.

Что получится на выходе

Скопируйте свой промпт в тело файла — и превратите его в инструкцию. Промпт отличается от скилла ровно четырьмя добавками. Пройдите по ним по порядку.

1. Проверка входов — что должно быть до начала

Что скиллу нужно, чтобы вообще начать: какой файл, какие данные, что вы должны приложить. И что делать, если этого нет.

## Шаг 0. Проверь входы

Тебе нужна выгрузка CSV с колонками: дата, менеджер, сумма.
Если файл не приложен или колонок не хватает — остановись и скажи,
чего не хватает. Не выдумывай данные и не считай по неполным.

Без этого пункта модель начинает работать с тем, что есть, и выдаёт правдоподобный результат на неполных данных. Это худший вид ошибки: он не выглядит ошибкой.

2. Причина у каждого правила

Самая недооценённая добавка. Правило с объяснённым последствием соблюдается заметно точнее, чем такое же правило без объяснения.

Промпт
«Пиши коротко, до 1000 знаков.»
Скилл
«До 1000 знаков. Это не пожелание по стилю: сводку читают с телефона в понедельник утром, и всё, что ниже первого экрана, не читают вовсе.»

Пройдитесь по всем своим требованиям и к каждому допишите «потому что». Если причину сформулировать не выходит — возможно, правило лишнее.

3. Пограничные случаи

Вспомните, когда результат вас не устроил, и опишите, что делать в таких ситуациях. Это то, что вы обычно дописываете в переписке уже после первого ответа.

## Особые случаи

- Данных меньше чем за 5 дней — скажи об этом и не сравнивай с прошлой
  неделей: сравнение будет бессмысленным.
- У менеджера ноль продаж — включи его в таблицу с нулём, не пропускай.
  Пропущенная строка читается как ошибка выгрузки.
- Отклонение больше 50% — сначала проверь, нет ли дубля в выгрузке.

4. Критерий готовности

По какому признаку работа закончена. Без этого модель останавливается раньше, чем нужно, и считает задачу решённой.

## Что считается сделанным

- Посчитаны все менеджеры из выгрузки, включая нулевые.
- Каждое отклонение больше 15% объяснено одной строкой.
- Текст укладывается в 1000 знаков.
- В конце — один вывод, а не пересказ таблицы.
Ориентир по объёму

Нормальный первый скилл — это полторы-две страницы текста. Если получилось пять строк, вы просто переписали промпт. Если получилось десять страниц, скорее всего внутри две разные задачи, и их стоит развести по двум скиллам.

9

Проверить, что скилл срабатывает

10 минут · терминал и правки
Что нужно на входе
  • готовый SKILL.md
  • реальная задача, на которой можно проверить
Что получится на выходе
  • скилл запускается от вашей обычной фразы

Запустите Claude Code в папке, где лежит скилл, и напишите задачу своими обычными словами — не именем скилла и не путём к файлу:

claude

А дальше, например:

Посчитай сводку за неделю, выгрузка в файле sales.csv

Проверяем две разные вещи, и путать их не стоит.

Что проверяемЧто смотрим
Скилл запустился? В начале ответа видно, что подхватился нужный скилл. Если нет — проблема в description, тело файла тут ни при чём.
Результат хороший? Если запустился, но сделал не то — проблема в теле скилла. Описание менять не нужно.

Не запустился

Вернитесь к description и добавьте в триггеры ту самую фразу, которую вы только что написали. Это не костыль, а нормальный способ настройки: вы буквально показываете, какими словами эту задачу просят.

Запустился, но сделал не то

Найдите в теле пункт, который не сработал, и допишите к нему причину или пограничный случай. Меняйте по одному месту за раз, иначе не поймёте, что именно помогло.

Самый быстрый способ отладки

Спросите у самой модели: «Ты только что выполнил задачу не так, как написано в скилле. Прочитай SKILL.md ещё раз и скажи, какая формулировка сбила с толку». Она разбирает такие вещи точнее, чем кажется, — и указывает на двусмысленности, которых вы не видите.

Прогоните скилл минимум на трёх разных задачах. Первый запуск почти всегда удачный по случайности; проблемы вылезают на втором и третьем.

Выложить скилл к себе

5 минут · браузер
Что нужно на входе
  • репозиторий из шага 3
  • работающий скилл
Что получится на выходе
  • скилл лежит в репозитории
  • ссылка готова к сдаче

Откройте свой ai-school-homework и загрузите файл так, как тренировались в шаге 4: Add file → Upload files.

Чтобы файл лёг в папку, перетащите папку целиком — или создайте файл через Add file → Create new file и впишите в имя путь:

skills/weekly-report/SKILL.md

В Commit message напишите по-человечески: «Добавила скилл для еженедельной сводки».

Перечитайте файл перед загрузкой

В скилле легко остаются рабочие подробности: имена клиентов, внутренние цифры, куски реальной переписки. Если репозиторий публичный, всё это увидят все. Замените конкретику на условные примеры — на качестве скилла это не скажется.

Что сдать

Четыре пункта. Первые два — доказательство, что механика освоена. Третий и четвёртый — собственно домашняя работа.

  • Ссылка на ваш репозиторий ai-school-homework. Если он приватный — добавьте преподавателя в Settings → Collaborators.
  • Ваш SKILL.md в этом репозитории.
  • Скриншот работающего скилла — видно вашу фразу и что скилл подхватился.
  • 5–7 предложений разбора: какую фразу вы написали в первый раз, сработал ли скилл, что именно вы поменяли в файле после первого прогона и что изменилось после.

Вопросы для самопроверки

Ответьте себе, прежде чем сдавать.

  1. Чем description отличается по назначению от тела скилла? Что чините, если скилл вообще не запустился?
  2. Почему нельзя положить в репозиторий файл .env?
  3. Вы написали в скилле «пиши коротко». Как переформулировать, чтобы это соблюдалось точнее, и почему это работает?
  4. Что произойдёт, если в скилле не будет раздела «что считается сделанным»?
  5. Ваш скилл сработал на первой задаче и не сработал на второй. Где искать причину?
  6. Чем Fork отличается от Download ZIP? В каком случае нужен первый?

Если что-то сломалось

Что видитеЧто делать
Не нашли папку .claude в распакованном архиве Она скрыта, потому что имя начинается с точки. В Finder нажмите Cmd + Shift + точка.
На GitHub нет кнопки «создать папку» Её и не бывает. Папка создаётся вместе с файлом: впишите путь в имя файла через косую черту.
Repository name подсветился красным Имя занято или в нём недопустимые символы. Пишите латиницей, без пробелов, через дефис.
GitHub заблокировал загрузку файла Сработала защита от секретов: в файле что-то похожее на токен. Уберите секрет и загрузите снова.
Скилл не запускается ни от какой фразы Проверьте шапку: три дефиса сверху и снизу, поле name совпадает с именем папки, файл называется ровно SKILL.md.
Запускается не тот скилл Описания двух скиллов слишком похожи. Добавьте в оба конкретики: с какими файлами работают и что отдают на выходе.
Скилл запускается, но игнорирует часть правил Скорее всего, правила даны без причин. Допишите к каждому последствие его нарушения.
Забыли пароль от GitHub На странице входа — Forgot password. Если потеряли доступ и ко второму фактору, восстановление занимает несколько дней, поэтому сохраните резервные коды сразу.
Универсальный приём

Скопируйте текст ошибки целиком и покажите его самой модели в окне claude: «вот такая ошибка, что не так?». В девяти случаях из десяти она объяснит причину быстрее, чем поиск в интернете.

Застряли дольше, чем на 15 минут, на одном шаге — не мучайтесь в одиночку. Напишите в чат группы, приложив скриншот целиком: чужая ошибка почти всегда чья-то уже пройденная.
